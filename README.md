# insol

Daily-mean insolation at the top of the atmosphere, for any latitude and any
time between 5 Ma before present and 1 Ma into the future, from the orbital
elements of Laskar et al. (2004).

The library was written for paleoclimate simulations and is used that way in
[yelmox](https://github.com/fesmc/yelmox). It also carries a separate module,
`irradiance`, for decomposing surface irradiance (DNI/DHI) in renewable energy
applications — see [Irradiance](#irradiance) below.

## Install

Configure and build with [configme](https://github.com/fesmc/configme):

```bash
configme install insol -m <machine> -c <compiler>
```

Or, in an existing checkout:

```bash
configme -m macbook -c gfortran   # writes ./Makefile
make static                       # -> libinsol/include/libinsol.a
make check                        # build and run the regression tests
```

The library has no external dependencies -- no netCDF, no fesm-utils -- so it
builds and tests with only a Fortran compiler.

## Use

Initialize a state object once, then query it. The state holds the orbital
tables and is read-only afterwards, so it is safe to share between threads.

```fortran
use insolation

type(insol_class) :: is
real(wp) :: insol

call insol_init(is)                              ! tables from ./input
call calc_insol_day(is,insol,170,65.0_dp,0.0_dp) ! day 170, 65N, 1950 CE
```

`insol_init` takes optional `fldr` (location of the orbital tables, default
`input`), `S0` (solar constant, default 1365 W/m²) and `day_year` (360, 365 or
366; default 360).

### Grids

If the latitudes are known up front — as they are for a model grid — pass them
to `insol_init`. It precomputes their geometry once, which is what makes the
per-day calls cheap, and the routines then need no latitude argument:

```fortran
real(dp) :: lats(nx,ny)
real(wp) :: insol(nx,ny)

call insol_init(is,lats)

do day = 1, 360
    call calc_insol_day(is,insol,day,time_bp)
end do
```

1D and 2D grids both work; `insol` must match the shape the state was
initialized with. A grid call on a state initialized without one is an error.

### Several days at once

```fortran
real(wp) :: insol(size(lats),size(days))

call calc_insol_days(is,insol,days,time_bp)           ! one column per day
call calc_insol_ave(is,insol_mean,[152,243],time_bp)  ! mean over a day range
```

`calc_insol_ave` takes an optional `step` to sample the range rather than
evaluate every day.

### Diurnal melt schemes

`calc_insol_day` takes an optional minimum solar elevation `elev_min`, so the
daily mean counts only the part of the day when the sun is higher than that
angle — what schemes like dEBM (Krebs-Kanzow et al., 2018) need. It can also
return the fraction of the day the sun is above that elevation and the
flux-weighted mean cosine of the zenith angle over it:

```fortran
real(wp) :: insol, tday, coszm

call calc_insol_day(is,insol,day,lat,time_bp,elev_min=17.5_dp,tday=tday,coszm=coszm)
!   insol       daily-mean flux, counting only when the sun is above 17.5°
!   tday        fraction of the day the sun is above 17.5°
!   insol/tday  mean flux while it is
```

`elev_min = 0` (or omitting it) recovers the plain daily mean exactly. On a grid
`elev_min` is one value per grid point, since dEBM estimates it locally.

### Conventions

- `time_bp` is years relative to 1950; negative is into the past.
- Latitudes are degrees north, in `dp`. Insolation is returned in `wp`, which is
  `dp` unless the library is built with `-DINSOL_SP`.
- `day_year` selects how the orbit is labelled, not a different orbit: the
  vernal equinox is pinned to March 21, 12:00 GMT, which falls on day 80.5 of a
  360-day year and 79.5 of a 365-day year.

## Accuracy

The daily mean is evaluated in closed form (Berger 1978) rather than by summing
over hours, so it carries no discretization error:

```
Q = S0 (a/r)^2 / pi * (H0 sin(phi) sin(dec) + cos(phi) cos(dec) sin(H0))
```

Tests compare against `tests/reference/insol_reference.txt`, generated by
`scripts/make_reference.jl` — an independent implementation in Julia that shares
no code with the library. The two agree to ~1e-12 W/m². The suite also checks
properties that hold regardless of implementation: the point and grid interfaces
must agree, insolation is non-negative and bounded, the winter pole receives
exactly zero, the equinox falls where the calendar says it does, and the global
annual mean equals `S0/(4*sqrt(1-e^2))`.

To regenerate the reference values:

```bash
julia scripts/make_reference.jl
```

### Solar position at a real date

For present-day work — a climate model on real time, or the irradiance
decomposition below — the geometry can be phased on a Gregorian date rather than
the idealized paleo calendar. This is the same orbital solution; only the clock
differs (see `src/insol_orbit.f90`, `calc_solar_position_date`).

## Irradiance

`irradiance.f90` estimates direct normal irradiance (DNI) from global horizontal
irradiance via the DISC model (Maxwell 1987), plus a Blanc & Wald (2016)
effective-zenith path for beam flux. It shares the orbital solution
(`insol_orbit`) with the core rather than carrying its own, so it uses real
dates and the same 1365 W/m² solar constant.

```fortran
use irradiance
use insol_orbit, only : orbit_class, orbit_init

type(orbit_class) :: orb
real(wp) :: dni

call orbit_init(orb, day_year=365)
call calc_dni_disc(orb, dni, year, hour, lat, lon, ghi, pres, .false.)
!   hour = hours since 00:00 UTC on 1 January of `year`; lon = degrees east
```

DISC is empirical, so it is tested against measured DNI in the NSRDB station
fixture (`tests/reference/nrel_stations.txt`) with a bound on the RMSE, ~52 W/m²
against a measured DNI RMS of ~558. The Boland (2013) and BRL paths remain
unfinished and untested — treat them with caution.
